# 窄桥（漏斗通道）寻路与人群行为优化全过程

> 项目：DesertStormUnitLab（团结引擎 2D）
> 场景：漏斗通道压力测试（`CorridorTestBootstrap`）——左侧 900 宽开阔生成区，100 个体积/移速各异的单位，经漏斗收束到 56 宽窄口（雷神直径 ×2），前往右侧集合点。
> 涉及文件：`CdtNavigationSystem.cs`、`UnitBase.cs`、`CorridorTestBootstrap.cs`、`UnitInspectorPanel.cs`

---

## 一、问题演化路径

优化历经四轮，每轮由用户实测截图反馈驱动，问题逐层暴露：

| 轮次 | 现象 | 根因层级 |
|---|---|---|
| 1 | 单位全部冲向左下角原点 | 寻路目标状态机（时序 bug） |
| 2 | 通道内单位加速，超出自身移速 | 转向层速度钳制 |
| 3 | 密集贴住后整团冻结（凝滞） | 物理层接触冲量 |
| 4 | 不再冻结，但快慢车挤成一团"整体蠕动"，无分层 | 转向层力分解方式 |

## 二、第一阶段：目标状态机修复（单位涌向原点）

**现象**：生成后 100 个单位全部聚集到左下角 (0,0)，而非前往右侧目标点。

**根因**：`UnitBase.Setup()` 在纯目标点模式（`useGoalPoint == true`）下仍然执行初始寻路，而此时 `goalPoint` 还是默认值 `(0,0)`——单位实际在冲向原点。

**修复**（三段式）：
1. `Setup()` 在目标点模式下跳过初始寻路，路径留空；
2. `SetGoalPoint()` 检测目标变化时立即重新寻路，承接首次路径请求；
3. `FixedUpdate()` 增加"路径为空且目标点为零"守卫，该帧保持静止，避免用默认值寻路。

**附带**：窄口 56 宽内没有网格采样点导致可见性图断链——y 网格起点从 140 降到 60，并增加轴线加密采样（每 80 单位一个点），窄段连通节点从 0 恢复到 8（Python 复刻 A* 验证）。

---

## 三、第二阶段：通道内加速（超速）

**现象**：单位在通道内速度明显快于面板标称移速。

**根因**：`SteerVelocity` 最终速度钳制写的是：

```csharp
return Vector2.ClampMagnitude(steering, Mathf.Max(1f, desiredVelocity.magnitude * 1.7f));
```

分离力、绕行力叠加后，慢速单位（如蟑螂期望速度 53）可被推到 90+（170%）。

**修复**：
- 最终钳制改为**精确等于自身移速**（1.0×）；
- 分离力封顶 0.8× 移速、绕行力封顶 0.55×，多邻居叠加不再矢量爆表；
- 高冲击单位推挤力 260 → 120，并删除"推人时给自己加前进速度"的逻辑（速度尖峰来源）。

**验证**（Python 复刻新旧算法，蟑螂 53.2 移速）：

| 场景 | 旧 | 新 |
|---|---|---|
| 单独行进 | 100% | 100% |
| 前方两台雷神 | **170%** | 100%，前进分量 88% |
| 8 邻居包围 | **170%**，前进分量 53% | 100%，前进分量 88% |
| 12 邻居贴脸 | **170%**，前进分量 55% | 100%，前进分量 84% |

## 四、第三阶段：密集凝滞（软体人群）

**现象**：速度正常了，但漏斗口呈拱形堵塞，单位贴住后整体近乎冻结。

**根因（物理层）**：单位之间是硬碰撞。每个物理步进中，接触冲量会把"顶住前方单位/墙体"的法向速度**清零**——前方一堵，后方全体速度归零，压力沿人群向后传播，整团冻结。转向层的"前进保底"只是速度意图，写入刚体后仍被接触冲量吃掉。

**修复（软体人群三件套）**：
1. **单位间关闭物理碰撞**（与墙保持硬碰撞）：`UnitBase.SoftBodyCrowd` 静态开关，单位统一挪到 Ignore Raycast 层并 `Physics2D.IgnoreLayerCollision(layer, layer, true)`；
2. **位置级去重叠**：`CdtNavigationSystem.ResolveOverlaps()` 在 LateUpdate 做 2 轮松弛推开——允许重叠至双方半径和的 45%，超出部分按质量加权各推一半。位置修正不清零速度，密集时表现为"挤而缓行"；
3. **卡死检测改为净位移判定**：滑动窗口锚点（`stuckAnchorPosition`），1.2 秒内净位移 < 半个身位才算真卡死才重寻路。排队缓行不再误触发全员高频 A*（原实现每 1.2 秒一轮，100 单位时是显著性能尖峰）。

**验证**（Python 微缩漏斗，40 单位 900 帧）：

| 模式 | 通过数 | 拥堵区平均前进速度 |
|---|---|---|
| 硬碰撞 | 13/40 | 11~15（冻结） |
| 软体 + 去重叠 | **39/40** | **53~73（流动）** |

## 五、第四阶段：分层流动（纵向压缩 / 横向保全 + 速度差超车）

**现象**：不再冻结，但快慢车挤成一团整体蠕动——移速不同的单位本应自然分开。

**根因**：
1. 上一轮的"同向流动折扣"把**横向分离力也**打到 0.35 折——横向分离正是快车滑向空隙、绕过慢车的通道；
2. 原绕行/推挤规则只在**友军**间触发且按 Impact（冲击）分级——漏斗测试 100 单位三族混编（互为敌对阵营）从未触发，且与移速无关。

**修复**（`SteerVelocity` 重构）：
1. **纵向/横向分解**：分离力分解后，纵向分量（沿行进方向）压缩到 40%（排队链收紧防追尾），横向分量保持全强度（保留超车通道）；
2. **速度差超车**（与阵营无关）：前方单位实际速度比自己低 35% 以上（且绝对差 >12）、横向偏移在车道范围内（双方半径和 ×1.1）时，施加侧向超车力（封顶 0.6× 移速）；超车方向延续相对位置所在侧，正后方用实例 ID 奇偶分配，避免抖动与扎堆一侧；
3. 同速单位不互相触发（阈值保护）。

**验证**（Python 2D 分层仿真，40 单位混速通道）：

| 版本 | 快车组平均通过 | 分层效果 |
|---|---|---|
| 上一版 | 6.5s（慢车 10.5s） | 弱（提前 4.0s） |
| 本版 | 6.4s（慢车 10.8s，让出通道） | **明显（提前 4.4s，中速组同步前移）** |

## 六、调参速查

| 参数 | 位置 | 作用 | 调节方向 |
|---|---|---|---|
| `MaxOverlapFraction` (0.45) | `CdtNavigationSystem` | 允许的最大嵌合深度 | 调低更"实"、调高更通畅 |
| 超车阈值 (0.35 / 12f) | `SteerVelocity` | 触发超车的速度差 | 调低更灵敏 |
| 车道宽度 (1.1f) | `SteerVelocity` | 判定"挡道"的横向范围 | 调大更容易触发绕行 |
| 纵向压缩比 (0.4f) | `SteerVelocity` | 排队链紧密度 | 调低更紧、更难超车 |
| 前进保底 (0.35f) | `SteerVelocity` | 拥堵时最小前进分量 | 调高更"硬" |
| 去重叠迭代 (2) | `CdtNavigationSystem` | 位置修正轮数 | 多轮会过校正 |

## 七、经验沉淀

1. **分层排查**：人群行为问题要区分"意图层"（steering 速度）与"物理层"（接触冲量）。速度写进刚体不等于速度生效——硬碰撞会清零法向分量。
2. **力要分解管理**：分离/绕行/超车力分开累计、分别封顶、按方向轴区别对待，比单一钳制更能同时满足"紧凑"与"流动"这两个矛盾需求。
3. **对称力场是凝滞之源**：密集人群中无方位加权的分离力会对称抵消，净位移趋零；打破对称（方位加权/纵向压缩）比单纯加大力度有效。
4. **仿真先行**：每轮修复均用 Python 复刻 C# 算法做数值验证（速度边界、通过率、分层度），再进引擎实测，避免盲调。
5. **统计口径要区分**：瞬时低速 ≠ 卡死。拥堵排队需要用"窗口净位移"判定，否则触发全局重寻路反而制造性能尖峰与抽搐。

## 八、配套功能：单位点选信息面板

最后一并加入了单位检视功能（`UnitInspectorPanel.cs`，静态类，两个场景通用）：

- **左键点击**单位小球 → 屏幕下侧中央显示属性面板（静态属性 + 实时状态两列）；
- 点击空白处取消选中；选中单位带白色圆环标记（随碰撞直径缩放、跟随移动）；
- **F 键**或面板右上"隐藏 [F]"按钮控制显隐，隐藏后底部中央保留"显示单位信息 [F]"快捷开关；
- 空格+左键拖拽视角不会误触发拾取；左右功能面板区域点击不穿透；
- 主场景切换到漏斗场景、漏斗场景"重新开始测试"时自动重置选中状态与标记。
