# 2026-10-06

## 兴奋剂施放条件修复（用户反馈）
- 用户症状：①没遇到敌人也施放；②血量低于 10 点代价仍在施放
- **根因 1（主犯）——池复用组件叠加**：UnitBase.Setup() 每次都 AddComponent<StatusSystem>/<AbilityComponent>，池复用 N 次的单位挂 N 个技能组件，各自独立施放（各自冷却、各自状态系统实例），一帧连环扣血 10×N，血条被打穿远低于代价仍"看起来在用"。修复：Setup 改为 GetComponent 优先复用，没有才 AddComponent
- **根因 2——交战判定过松**：HasEngagedInCombat 是终身粘性标志（打假人/被打一下/攻击过就置位），冷却好转后行军途中也再施放。修复：新增 IsEngagingEnemy（逐帧刷新 = 敌对单位目标在射程内），AbilityComponent 门槛从 HasEngagedInCombat 换成 IsEngagingEnemy；HasEngagedInCombat 保留供兴奋剂外的历史交战参考（受击方被动判定等）
- **双保险**：Cast() 施放前最终校验 IsEngagingEnemy + CurrentHealth > hpCost（防外部手动调用绕过）
- **池复用状态残留**：StatusSystem.Initialize 清空 active 列表并 Recalculate 复位共享 UnitData 修正器；AbilityComponent.Initialize 清零冷却——上一世的兴奋剂状态/冷却不带到新单位
- 旧血量判定 `CurrentHealth <= hpCost` 本身正确（施放后留 1 点），用户看到的"血量不足还烧"实际是组件叠加的连环扣血
- 教训：AddComponent 挂"常驻组件"必须先查重——对象池场景下 Setup 会被同一 GameObject 反复调用；粘性标志（HasEngagedInCombat）与逐帧状态（IsEngagingEnemy）语义不同，自动技能门槛用后者
- 离线编译 exit 0 零错误
